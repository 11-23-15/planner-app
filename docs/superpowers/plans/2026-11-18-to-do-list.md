# To Do List Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Build a responsive daily task planner with per-user Supabase sync and prepare a public GitHub repository for school review.

**Architecture:** A React/TypeScript/Vite client uses Supabase Auth and Postgres. Row Level Security isolates every user's tasks. The first release is local code plus a public GitHub repository; public website hosting is excluded until separately approved.

**Tech Stack:** React, TypeScript, Vite, Supabase JS client, CSS.

**Spec:** `docs/superpowers/specs/2026-11-18-to-do-list.md`

## Global Constraints

- Use only the approved features in the spec; do not add reminders or collaboration.
- Keep all personal task data in Supabase; do not put it in Git.
- Never commit `.env`, Supabase secret keys, or service-role keys.
- Do not publish the site without separate user approval.
- Do not spend money or choose a paid plan without user approval.

## Review Focus

- Unauthenticated users must not read or change task rows.
- One account must never see another account's tasks.
- A task's date and priority must survive refresh and sync.
- Daily progress must handle zero tasks without division errors.
- Public source code must contain no credentials or personal task data.

### Task 1: Scaffold the planner

**Files:** Create `package.json`, `index.html`, `src/main.tsx`, `src/App.tsx`, `src/styles.css`, `tsconfig.json`, `vite.config.ts`, `.gitignore`, `.env.example`.

**Deliverable:** A responsive application shell with selected date, task list, three priority labels, and a daily progress ring. No test files or test commands are included.

- [ ] Scaffold the Vite React TypeScript app in this empty folder.
- [ ] Build the responsive planner screen and accessible controls.
- [ ] Add the progress ring with a safe empty-day state.
- [ ] Add local-only task interactions for create, edit, complete, delete, date selection, and priority.

### Task 2: Add Supabase persistence and access rules

**Files:** Create `src/lib/supabase.ts`, `src/lib/tasks.ts`, `supabase/schema.sql`; modify `src/App.tsx`, `.env.example`.

**Interfaces:** `Task` has `id`, `user_id`, `title`, `task_date`, `priority`, `completed`, `created_at`; `tasks.ts` exposes list/create/update/delete operations scoped to the authenticated user.

- [ ] Define the task table and enable RLS with owner-only policies for select, insert, update, and delete.
- [ ] Add Supabase client initialization using only the project URL and publishable key.
- [ ] Add account registration, sign-in, and sign-out screens.
- [ ] Replace local-only persistence with authenticated Supabase operations and loading/error states.

### Task 3: Prepare Git and public GitHub repository

**Files:** Create or modify `.gitignore` and project documentation as needed.

- [ ] Inspect Git and GitHub authentication availability; do not expose tokens or passwords.
- [ ] Initialize Git in this project folder and inspect the staged file list for secrets.
- [ ] Create a public repository named `to_do_list` only in the user's authenticated GitHub account.
- [ ] Push the project files and return the resulting repository URL.

### Task 4: Final handoff

- [ ] Summarize the completed features and any Supabase setup that still requires the user's own account.
- [ ] State clearly that the website is not deployed until separate approval.

## Coverage Notes

The spec's user-facing features map to Tasks 1–2. GitHub source sharing maps to Task 3. Public site hosting is explicitly excluded. Per developer instruction, this plan does not add or run automated tests.
