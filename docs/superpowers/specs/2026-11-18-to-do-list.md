# To Do List — дизайн

## Назначение

Личный планировщик для ежедневных задач. Юля должна добавлять дела, отмечать выполнение, видеть прогресс за день и открывать свои данные с разных устройств.

## Цели

- Создание, редактирование, выполнение и удаление задач.
- Дата задачи и один из трёх приоритетов: «Срочно», «Второстепенно», «Можно потом».
- Кольцо и числовой показатель выполнения задач за выбранный день.
- Вход в аккаунт и синхронизация задач между устройствами.
- Удобная работа на телефоне и компьютере.

## Не входит в первую версию

- Публичные списки задач, совместная работа, напоминания и календарные интеграции.
- Публикация сайта в интернете — её отдельно согласуем до настройки хостинга.

## Решения

- **Интерфейс:** React + TypeScript + Vite; адаптивный одностраничный веб-интерфейс.
- **Данные и вход:** Supabase Auth и Postgres. У задачи есть владелец; включённые политики Row Level Security разрешают пользователю работать только со своими строками.
- **Публикация кода:** публичный GitHub-репозиторий, чтобы школа могла открыть ссылку. В GitHub не помещаются секретные ключи или пользовательские задачи.
- **Хостинг:** не настраивать и не публиковать сайт без отдельного согласия.

## Что остаётся решить при настройке

- GitHub-аккаунт, имя владельца репозитория и наличие авторизации для создания репозитория.
- Supabase-проект и его URL/публичный ключ; секретный ключ в клиентское приложение не добавлять.
- Вариант хостинга и публикация сайта.

## Подходы

1. **GitHub Pages + Supabase:** простой путь к сайту по ссылке; исходный код и сайт публичны. Данные задач доступны только после входа при корректно настроенных RLS-политиках. Выбран для рассмотрения после отдельного согласия на публикацию сайта.
2. **GitHub только для кода + отдельный хостинг:** приватность репозитория может быть гибче, но появляется второй сервис и отдельная настройка.

Для школы выбран публичный GitHub-репозиторий с кодом; ни один вариант публикации сайта пока не выбран.

## Защита данных

- Таблица задач должна включать `user_id` и политики RLS для чтения, добавления, изменения и удаления только владельцем строки.
- В браузер можно помещать только публичный Supabase publishable/anon key; `service_role` и secret keys запрещены.
- Переменные окружения и локальные `.env` не коммитить; добавить `.env.example` без реальных значений.
